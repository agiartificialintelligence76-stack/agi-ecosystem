## Implemented terminal

- Dense discovery table, narrow navigation rail, watched-token strip, top search and balance controls, footer
  ticker, and right-side open/closed positions. Responsive layouts preserve access on a 360 px phone.
- Independently configurable Tokens, Watchlist, Feed, Leaderboard, Alerts and Perps panels; split horizontally or
  vertically, close, reset, resize, and persist up to four panels. The default is one main token table.
- Trending, Blue chips, Most held, Graduated, Bonding and Watchlist categories; 25/50/100 results; sorting;
  market-cap, liquidity, age, volume, holder and percentage filters; network and source filters for the markets
  actually present in the run. Search supports token names/tickers, simulated traders and supported contract lookup.
- Dollar quick buys through the existing practice order path. Coin pages include the shared candlestick chart,
  timeframes, market-cap/price views, indicators, trade markers, holders/activity, token details, watch/hide,
  local theses and swap controls. Buy presets, percentage sell presets and Auto/Custom slippage are editable and saved.
- Portfolio/profile views, optional player-name editing, position cards, simulated trader profiles and rankings,
  follow/mute, local likes/theses, explicit one-tap copy orders, and one-shot price/market-cap/trader alerts.
  Weekly ranking controls use the selected weekly metric and display matching amounts.
- Live-feed status distinguishes connection interruptions from live quotes. Source-filter choices refresh as new
  sources arrive; saved filters recover when switching between simulated and live markets.

The data model shares cached metrics across panels and bounds candidate scans and stored preference books.
Preferences use `trench_phomo_v1`, separate from the existing game save. Public model entry points are
`createPhomoState(market, options)` and the pure helpers in `boards/phomo-data.js`.

## Data and action boundaries

- Everything in spot trading settles against the existing **play-money** engine. No wallet connection, real
  deposit, signature, trade execution, automatic social posting or automatic copy-trading was added.
- Trader characters and their prior-week histories are explicitly simulated. The local feed combines those
  simulation events, the player's practice orders and private notes. Follows, likes and notes stay on this device;
  they are not a public social network or evidence that a real wallet traded a live token.
- Live token prices/token counts use the engine's normalized **practice units** and are labeled accordingly.
  Market cap follows the real feed. Unknown real supply, holder identities and synthetic fallback liquidity stay
  unavailable. Four-hour/day statistics require retained coverage; a shorter observed total is not relabeled as 24h.
- Blue chips is a disclosed game filter (market cap at least $1M and liquidity at least $50K), not a safety rating.
  Network filters do not change a run's chain or imply a simultaneous feed for every chain.
- Price alerts operate while the game is open. A copy button places one practice order using the chosen dollar
  amount or the player's own holding for a sell. There is no background auto-copy subscription.
- **Perps are view-only.** The relay reads public Hyperliquid market groups, quotes and candles, including markets
  offered by supported groups. The panel has search/sorting, venue selection, real quote metrics, timeframe
  selection, and chart zoom/pan. There is no derivatives ledger, leverage position, funding payment, liquidation,
  wallet/account query or order API. Unknown/stale data is handled explicitly; no extra API key is required.
- The existing safety note remains. Phomo's dollar runs do not acquire a new ranked-results submission path.

## Replay

The result screen now offers **Replay this run**. `captureRunReplay(run)` in `replay-data.js` synchronously captures
an immutable record before `stopPlay()`. The lazily loaded `mountReplay(host, record)` in `replay.js` returns
`destroy()` and runs independently of the game.

Controls: play/pause, 1×/2×/4× speed, time scrubber, previous/next filled trade, token selection and chart timeframe.
The view displays recorded market-cap candles, portfolio history and orders. Order results appear at their actual
recorded completion times; backward seeking restores pending/unknown states correctly.

Both modes use recorded playback. Complete simulated seed/config/order-step logs can reconstruct the same market
and are verified in tests. Live runs **never** re-simulate real prices, invent launch history or fill missing gaps.
Final OHLC values are revealed only after the retained candle completes; intrabar movement is not reconstructed.

Bounds: 300 orders, 100 tokens, 2,000 candles per token with a 20,000-candle total cap, 2,000 portfolio observations,
and a complete simulation log only when it fits the 300-entry limit. Coverage/truncation is disclosed. Selecting
an order whose older token chart was not retained shows unknown history rather than another token's chart.
The record belongs to the last run in this page session; it is not a persistent replay library. Playback cannot
place trades, submit a score or contact a wallet/live feed.
